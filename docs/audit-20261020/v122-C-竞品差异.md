## 一、当前位置判断

这个赛道有三条轴，PulseWin 在三条轴上的位置完全不同：

| 轴 | 头部在做什么（记忆值） | PulseWin | 判断 |
|---|---|---|---|
| 覆盖广度 | CodexBar 22,011★、60+ provider、**官方明说没有 Windows 版**；token-monitor 2,430★、37+ 工具；上游 Pulse 25 provider（v1.6.1，09-28） | 3 个订阅额度源 + 3 个本机账本 | 绝对劣势。这条轴上追不上，也不必追 |
| 报表深度 | ccusage 18,774★ 是 CLI 报表事实标准；codeburn 11,265★（浪费扫描／健康分级／预算守卫／模型对比／session↔git 归因）；claude-devtools 3,951★（会话检查器）；Maciek 8,727★（预测／节奏／官方信任层，**pushed 2026-07-05 已近 3 月未更新**） | 曲线、热图、下钻、峰谷拆分、CSV/JSON 导出、环比、平均输出速度——09-19 清单的"推荐档"除托盘仪表化（v1.12.2 用户否掉）外均已落地 | 已齐平同体量竞品，**不再是短板** |
| 数字可信 | Maciek 有 provenance 标签（给数字标来源）；WhereMyTokens 82★ 有历史校验修复 | 四类 token 对不上进"未分类"、无价不显示 `$0.00`、读不出要说出来、官方口径对照卡 | **唯一的强项，但今天只是个脚注** |

再叠三条本机事实（决定"现在缺什么"）：

1. **rail 上只有 2 条环**（`VisibleSources` = opencode/deepseek；GOAT 的 `snapshot.json` 停在 09-30、PlanId 未知、剩余 0 credits）。"三个订阅"是能力，不是每天都在用的现状。
2. **最能吃额度的那条通道没有分母**：`BigModelMonthlyBudgetCny` 为 null，而按记忆 `glm-heavy-usage-two-subscriptions`，重活（日耗 1 亿 token 量级）走的正是 GLM/BigModel 包月——它恰好是唯一没有额度接口、也没填预算的那条。
3. **没有任何额度读数历史**：`usage-history.sqlite` 只有 `agg_day` / `agg_hour` / `seen` 三张表（已读 schema 核实），全部是 token 聚合。所有"预测／浪费"类功能今天起步才有数据。

**结论**：v1.21.x 已把界面层的"必错数"清零（`views-audit` §0：P0 = 0，剩 4 条 P1 全是体验／资源类），继续修工业卫生的杠杆很低。PulseWin 现在的位置是——**一个把"数字怎么说才不算撒谎"做到极致的仪表，但它只回答"用了多少"，不回答"这个数能不能信、额度到底去哪了"**。而"用了多少"这条轴上是 2 万星、37+ 工具的对手。要做的不是在同一条轴上往前挤半步，是把已有的"两侧数据同时在手"这个结构变成独占产出。

## 二、三个候选方向

### 方向一（推荐）额度对账台——把"本机 vs 官方"的差判成结论，而不是一个数字

- **一句话**：每个订阅给出"两侧读数 + 差值 + 归因 + 置信度"，并回答"本机账本这一段完整吗"。
- **谁需要**：同一台机器上跑 2–3 个客户端（ZCode／OpenCode／DSH）、额度按账号聚合、且还有第二台设备或第二把 Key 的人。具体动作：官方说本周已用 62%，本机账本只算出 41%——剩下 21% 是我另一个 CLI 跑的、是另一台机器、还是官方当天没结算？今天程序只给一个差值格和一段脚注，不给判定。这条判断已经被真实触发过两次：v1.21.3（一把过期 Key 让整源静默停更 10.3 小时）、v1.21.6（官方当日未结算，本机反超官方 4,848.7 万）。
- **竞品做了没有**：**跨侧归因未调研到**。相邻的两条必须点明——Maciek 做过"官方限额信任层 + provenance 标签"（单侧标注来源，**已有人做，不能当差异**）；WhereMyTokens 做过"历史校验修复"（本机自校验）。所以差异化**只能落在"跨侧归因 + 可信度判定"上**：它要求官方读数与本机会话账本同时在手，是结构性门槛，不是功能点先后。
- **成本**：**小—中**。数据全在手（额度条、官方对照卡、本机聚合、`Diagnostics`）。要加的是：①两侧读数每次同步落一条（新表／JSONL，代码量几十行）；②归因规则（未结算／他端真实差异／本机漏记／量纲不同——量纲这条 v1.14 已在 OpenCode Go 上处理过）；③把脚注换成结论行 + 一个"账本完整度"标记。改动面约 2–3 个文件 + 1 个新服务类，不新增数据源。
- **风险**：归因误判比不判更糟 → 必须留"无法判定"档，与项目既有的口径诚实一致。

### 方向二 重置残留——把"用了多少"翻成"白扔了多少"

- **一句话**：每个窗口重置那一刻还剩多少，折算成本周期作废掉的已付额度。
- **谁需要**：按包月／周额度限额的订阅者，要回答"这份订阅值不值、该不该降档"。具体：月额度 10-28 重置，重置时还剩 30%，这个月就白扔三成；连续三个月如此，降档是有依据的决策。
- **竞品做了没有**：**未调研到**。必须区分清楚：codeburn 的 waste scan 扫的是"单次请求里浪费的 token"、guard 是预算上限；Maciek 的持久仓库解决的是"别丢历史"；**"订阅周期结束时作废的已付额度"这一笔账没人做**。
- **成本**：**小—中，但有启动延迟**。计算纯离线、不难；难在数据——今天没有额度读数历史（见上），必须从新版起每 N 秒落一条，**至少满一个月才有第一份月度结论**。
- **排序理由**：正因为要等一个月，越晚建表第一份结论越晚。所以它应该是"现在建表、v1.23 出结论"，而不是等做到它那天才建。

### 方向三 无接口通道的额度自证（BigModel 包月）

- **一句话**：没有官方额度接口的通道，用手填预算 + 本机账本反推"还剩多少、几号用完"。
- **谁需要**：把重活压在 BigModel 包月（无用量接口）的人。今天的实际状态是：这一行"只有填了预算才有进度条"，而预算为空 → 唯一吃大额度的通道没有分母，`月底预测` 这段逻辑写好了却没分母可用。
- **竞品做了没有**：**未调研到**，但要打折——记忆里 25 个 provider 只逐个点名了 Kiro／Sub2API／New API／V2EX／Qoder／StepFun，未列全，所以"没有 BigModel"是"未调研到"而非"确定没有"；另外上游 Pulse 对"无价用量"只是**不再显示 `$0.00`**（v1.4.0），并没有解决"没有分母"。
- **成本**：**中**（预算校准 UX + 上限反推 + 跨月对比；月底预测逻辑已有，缺的只是分母与校准）。
- **为什么排最后**：差异化被绑在"某一家恰好没接口"上，官方一给接口就作废；而且答案质量取决于用户填的那个数，容易输出与"口径诚实"身份冲突的假精度。

### 对比表

| | 方向一 对账台 | 方向二 重置残留 | 方向三 无接口自证 |
|---|---|---|---|
| 回答的问题 | 这个数能不能信／额度去哪了 | 这份订阅值不值 | 没接口的通道还剩多少 |

| 成本量级 | 小—中 | 小—中（含等待） | 中 |
| 复用性 | 每加一个通道都自动受益 | 每类窗口都受益 | 只对无接口通道 |
| 排序 | **1** | 2 | 3 |

## 三、推荐与理由：只选方向一

1. **它是唯一抄不走的**：竞品要么有官方额度没本机账本（CodexBar 60+ provider），要么有本机账本没官方额度（ccusage／token-monitor 式统计）。"两侧同时在手"是 PulseWin 独有的结构，对账是这种结构的唯一独占产出——新入场的团队没有一个能靠加功能追平，因为他们缺的不是功能，是这一侧的读取器。
2. **它把已有强项从脚注提成产品**：官方对照卡 v1.14 就有了、v1.21.6 刚修过口径，现在只是一个差值格加一段脚注。v1.22 不新增任何数据源，只是把已经存在的判断力显性化——这是低成本高差异的少数位置。
3. **它顺手吃掉一批已知隐患**：v1.21.7 留的"`RangeHourly` 只覆盖 35 天却标整个区间累计"、截断结果、凭据过期导致的长时间停更，在"账本完整度"这一层会变成用户看得见的状态，而不是等以后某天自己撞见。
4. **它给方向二免费铺路**：对账需要两侧读数按次落盘，这张表正是"重置残留"要的那张表。v1.22 建表 = 方向二提前一个月开始攒数，边际成本接近 0。这是把它们放进同一版的唯一理由。
5. **反过来看**：选方向三 = 把差异化押在"智谱短期不给接口"上；选方向二 = 先空等一个月才有第一句结论。都不如方向一。

**v1.22 最小切口**（只定边界，不写代码）：每个套餐页的官方对照区，从"三格 + 脚注"改成"三格 + 一行判定 + 一个完整度标记"；判定档位固定五档——未结算（当日）／他端真实差异（历史日）／本机漏记／量纲不同／无法判定。验收一句话：**每个差值都必须落到一个档位；落不进去的一律显示"无法判定"，不许猜。**

## 四、不做什么

- **不加 provider、不加图表**：09-19 清单的"推荐档"已基本落地，剩下的差距只在广度，而广度是 2 万星对手的战场。加数据源不解决任何一个具体卡点（`glm-heavy-usage-two-subscriptions` 说得很清楚：重活就集中在一两条通道）。
- **不把耗尽预测当主线**：Maciek 已做过"预测／节奏"，先例在前不构成新鲜差异化；且那个仓库 07-05 后未更新，抄一个停更产品的功能只会得到"又一个百分比"。可以做成对账台里的一行附注。
- **不做"下一条重活走哪个通道"的路由建议**：记忆 `prefer-single-provider-channel` 写明用户偏好全走同一套餐、宁慢不混第二条通道；而且建议错了要背锅。
- **不做会话检查器**：claude-devtools 已做到 context 重构／子代理树／工具调用／compaction 可视化，token-monitor 也有 per-session 下钻，正面撞车且不服务"额度还剩多少"这个真问题。
- **不加强通知告警**：越线弹一次泡已经够；记忆的"不建议"档里通知告警本来就在列（预算守卫同理——订阅制没有按 token 计费的压力）。
- **不碰老雷**：浏览器 cookie 解密（CodexBar-Win 因解密 cookie 被 AV 全家误杀成 infostealer 的先例）、多账户、3D／主题工作室、液态玻璃（Windows 无对等 API）。
- **不把"账本完整度"做成红色告警**：它是解释层，不是报警层——越线弹泡是用户已经删过一轮的东西。
